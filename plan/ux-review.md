# UI/UX 檢討與改進建議

> 基準:2026-07 `main`(d2fccb7)。範圍涵蓋 `public/index.html`、`public/app.js`、`public/style.css`,並對照 `src/game.ts`、`src/index.ts` 的實際節奏(20 秒回合、限制彈窗 3 秒緩衝、結算停留 7 秒)。

## 一、現況流程盤點

```
首次進入 ─ 命名頁(暱稱 + 帳號代碼登入/備份)
   │
   ▼
開始頁 ─ 模式切換(普通/惡魔)─ 排行榜 ─ 遊戲說明
   │  開始配對
   ▼
配對中(spinner,「等待對手加入…」)
   │  雙方到齊
   ▼
對戰畫面 ─ 記分板(暱稱/分數/ELO/超時額度)
   │        計時條(20s)+ 惡魔限制橫幅
   │        句子(slot 點選 → 輸入一字 → 放入)或 挑戰
   ▼
挑戰 → 「AI 裁判評分中」→ 結算彈窗(評語+計分明細+分數變化,7 秒自動下一回合)
   ▼
先達 5 分 → 結束彈窗(勝負 + ELO 變化)→「再玩一場」= location.reload()
```

## 二、做得好的部分(保留)

- **結算透明度高**:AI 評語、逐項計分明細、before → after 分數變化,把「為什麼得分」講清楚,是這款遊戲最容易產生爭議的點,現在處理得不錯。
- **限制彈窗的公平性設計**:阻擋 3 秒同時後端把 3 秒加進 deadline,不吃玩家的 20 秒,前後端一致。
- **斷線重連**:sessionStorage 記住對局、自動重連取回結果,不會停在死畫面(多數情況)。
- **超時額度**:小圓點 + 脈動 + 「+10 秒」浮動提示,低調不搶畫面。
- **手機優先**:safe-area、dvh、觸控回饋縮放、單欄 480px 版心都到位。

## 三、問題與建議

優先級定義:**P0** 明顯卡住或流失玩家、**P1** 顯著影響體驗、**P2** 打磨項。

### P0-1 配對中沒有出口

- **現況**:`screen-matching` 只有 spinner 與文字。沒有對手時會停在「等待對手加入…」直到永遠;想放棄只能重新整理。
- **建議**:
  - 加「取消配對」按鈕:關閉 WS、回開始頁(後端 `Lobby` 的 waiting 項需一併清除或靠既有 `WAIT_TTL` 過期)。
  - 顯示已等待秒數;超過 30~60 秒給提示(「目前沒有其他玩家,邀請朋友一起玩?」+ 複製網址按鈕)。
  - 中長期:提供「和 AI 對戰」墊底選項,冷啟動期沒有真人也玩得起來。
- **涉及**:`public/index.html`、`public/app.js`(`play()`/`connect()`)、`src/index.ts`(Lobby)。

### P0-2 「再玩一場」= 整頁重載

- **現況**:`showGameover()` 的按鈕 `onclick = () => location.reload()`,回到開始頁後還要再按一次「開始配對」;重載也重跑 boot/register。
- **建議**:改為兩個按鈕:「再玩一場」直接以原模式呼叫 `play()`(重置 state 即可,不重載);「回主選單」回開始頁。連勝想繼續打的玩家少兩步。
- **涉及**:`public/app.js`(`showGameover`、需要一個乾淨的 `resetGameState()`)。

### P0-3 惡魔模式規則在遊戲說明中完全缺席

- **現況**:說明頁只有普通規則;四種限制(位置/注音/詞性/意思改變)的說明第一次出現是在對戰中 3 秒的 toast,玩家邊倒數邊讀規則。開始頁的模式描述也只有一行抽象文字。
- **建議**:說明頁加「😈 惡魔模式」區塊,列出四種限制、違規罰則(+3)、疊加規則(開局 1 個、每 5 字加 1 個);模式切到惡魔時提供「查看限制種類 ›」連結直達該區塊。
- **涉及**:`public/index.html`(screen-help)、`public/app.js`(mode 切換)。

### P1-1 放字操作:目標太小、順序死板、沒有預覽

- **現況**:
  - slot 寬 14~22px(`style.css` `.slot`),遠低於 44px 的觸控目標建議;句子變長後 slot 更密。
  - 按「放入」前看不到字放進去句子會長什麼樣,只能腦補。
  - hint 只教「先點位置、再輸入字」,實際上先輸字再點位置也可行,但介面沒表達。
- **建議**:
  1. 用 `::before` 或透明 padding 把 slot 點擊熱區放大到至少 32~40px(視覺可維持細線)。
  2. **放入預覽**:選了位置且輸了字時,直接在句中以半透明樣式顯示該字(ghost char),按「放入」才成立。這一項對「意思改變限制」尤其重要——玩家需要看到完整句子判斷句意。
  3. 順序自由化的提示:「輸入一個字,點選要放的位置」兩者皆可先做。
- **涉及**:`public/app.js`(`renderSentence`/`selectSlot`/`updateControls`)、`public/style.css`。

### P1-2 結算彈窗 7 秒固定,不能跳過也不能延長

- **現況**:`RESULT_MS = 7000` 由後端 alarm 推進;彈窗資訊量大(句子+評語+明細+分數變化),讀得慢的人不夠、看過的人嫌久。倒數條也沒說明倒數完會發生什麼。
- **建議**:
  - 倒數條旁加文字「即將開始下一回合」。
  - 加「準備好了」按鈕:雙方都按下即提前開始(後端收 `ready` 訊息、兩人到齊就取消 alarm 直接推進);單方按下顯示「等待對方…」。保持 7 秒為上限。
- **涉及**:`src/game.ts`(結算階段訊息)、`public/app.js`(`showSettled`)。

### P1-3 輪到你了,但玩家不一定知道

- **現況**:回合切換只有 badge 變色與 hint 文字,無聲音、無震動、無分頁標題提示。手機上切去回訊息再回來,可能已被超時。
- **建議**:
  - 輪到自己時 `navigator.vibrate(100)`(靜默降級)+ 可選音效(設定開關,存 localStorage)。
  - 剩 5 秒時的紅色計時條配一次短震動。
  - 分頁在背景時把 `document.title` 改成「🔔 輪到你了 – 一字接龍」,回到前景還原。
- **涉及**:`public/app.js`(`applyRound`/`startTimer`)。

### P1-4 挑戰的風險與對象不夠明確

- **現況**:挑戰是核心決策,但對戰畫面沒有任何「挑戰失敗對方會得分」的提示(只在說明頁);挑戰針對的是「對方上一個字」,雖有 `.latest` 高亮,但高亮的語意(這就是被挑戰的字)沒有被說明。
- **建議**:
  - 挑戰按鈕可用時,hint 或按鈕副標帶一句「覺得『X』不合理?挑戰失敗對方得分」——把被挑戰的字直接寫出來。
  - 首次挑戰(localStorage flag)彈一次輕量確認,說明勝負規則,之後不再打擾。
- **涉及**:`public/app.js`(`updateControls`/`doChallenge`)。

### P1-5 斷線重連失敗後是死路

- **現況**:重連 4 次失敗後只顯示「連線中斷」,沒有任何按鈕;`judging` 若 LLM 卡住,前端也會停在「AI 裁判評分中…」沒有退路(後端雖有 fallback,但網路層失敗時前端收不到 `settled`)。
- **建議**:
  - 「連線中斷」畫面加「重試」與「回主選單」按鈕。
  - `showJudging` 設 15~20 秒前端 timeout:超時顯示「裁判逾時,重新連線中…」並觸發 reconnect 流程。
- **涉及**:`public/app.js`(`ws.onclose`/`showJudging`)。

### P2-1 排行榜看不到自己的名次

- **現況**:只取前 20;自己不在榜上時完全沒有參照。榜單也不分模式。
- **建議**:榜單底部 sticky 一列「你:第 N 名 · X 分」(後端 `/api/leaderboard` 回傳自己的 rank,或另加 `/api/rank?id=`)。
- **涉及**:`src/db.ts`、`src/index.ts`、`public/app.js`。

### P2-2 帳號代碼:遺失即失去帳號,但備份提醒藏太深

- **現況**:代碼只在「修改暱稱」畫面出現;多數玩家取完名字就再也不會進去,直到換手機才發現積分回不來。錯誤回饋用 placeholder 顯示(「找不到此帳號…」)也容易被忽略。
- **建議**:
  - 在有意義的時刻提醒一次備份:例如第一場勝利的結算畫面加一行「💾 備份帳號代碼,換裝置不掉分 ›」。
  - 登入錯誤改為輸入框下方的紅色文字,不要清空使用者輸入的代碼(方便修正打錯的字元)。
- **涉及**:`public/app.js`(`importAccount`/`showGameover`)。

### P2-3 限制 toast 強制等 3 秒,不可提前關閉

- **現況**:toast 遮罩吃掉所有點擊 3 秒。deadline 是後端固定給的,提前關閉不影響公平——先讀完的玩家只是提早開始思考。
- **建議**:允許點擊遮罩提前關閉(`hideRestrictionToast()` 已可直接呼叫);toast 上標示「點擊任意處關閉」。常駐橫幅已保留完整限制內容,不怕玩家漏看。
- **涉及**:`public/app.js`(`showRestrictionToast`)。

### P2-4 注音限制對不熟注音的玩家不友善

- **現況**:「字的韻母須為 ㄢ ㄤ」這種描述,對注音不熟(或非台灣)的玩家無從下手。
- **建議**:限制說明附 2~3 個範例字(「如:安、山、廣」),從後端產生限制時一併附上,或前端內建小型對照表。
- **涉及**:`src/devil.ts`、`public/app.js`(`restrictionHtml`)。

### P2-5 對戰中沒有明確的離開方式

- **現況**:中途想走只能關頁面(斷線判負),對玩家不誠實也容易誤觸離開。
- **建議**:對戰畫面角落加低調的「離開」按鈕,confirm「離開將判負,確定?」後正常送 leave;避免玩家用關頁面猜規則。
- **涉及**:`public/index.html`、`public/app.js`、`src/game.ts`(已有 leave 處理)。

### P2-6 無障礙(a11y)基礎缺口

- **現況**:
  - slot 是 `div` + click,無 `role="button"`/`tabindex`,鍵盤與螢幕閱讀器完全無法放字。
  - 回合切換、hint、計分變化皆無 `aria-live`,非視覺使用者收不到任何狀態。
  - 動畫(spinner、pulse、blink)未尊重 `prefers-reduced-motion`。
- **建議**:slot 加 `role="button"`、`tabindex="0"`、`aria-label="放入第 N 個位置"` 與 Enter/Space 觸發;`#hint` 與 `#turn-badge` 加 `aria-live="polite"`;加一段 `@media (prefers-reduced-motion: reduce)` 關閉裝飾動畫。
- **涉及**:`public/app.js`(`renderSentence`)、`public/style.css`。

### P2-7 其他打磨

- **配對頁顯示所選模式**:「😈 惡魔模式 · 配對中…」,避免玩家懷疑自己按錯。
- **超時額度圖示教育**:首場對戰第一次渲染 quota 時,hint 帶一句「⏳ = 超時額度,超時自動 +10 秒」;`title` 屬性在手機上無效,不能依賴。
- **結束畫面補場次資訊**:勝負彈窗可加本場回合數、最長句子等小統計(`game_events` 已有資料),增加分享/回味價值。
- **淺色模式**:目前僅深色。優先級最低,但若目標族群含日間通勤玩家可排入。

## 四、Quick Wins(改動小、收益高,建議先做)

| # | 項目 | 對應 | 預估工作量 |
|---|------|------|-----------|
| 1 | 配對中加「取消」按鈕 + 等待秒數 | P0-1 | 小 |
| 2 | 「再玩一場」不重載、直接重配對 | P0-2 | 小 |
| 3 | 說明頁補惡魔模式規則 | P0-3 | 小(純內容) |
| 4 | slot 點擊熱區放大 | P1-1 (1) | 小(純 CSS) |
| 5 | 輪到你時震動 + 分頁標題提示 | P1-3 | 小 |
| 6 | 限制 toast 可點擊提前關閉 | P2-3 | 極小 |
| 7 | 連線中斷畫面加重試/回主選單 | P1-5 | 小 |

## 五、建議路線圖

1. **第一批(當週)**:Quick Wins 全部 —— 都是前端小改,不動協定。
2. **第二批**:放入預覽(P1-1 (2))、結算「準備好了」提前推進(P1-2)、挑戰風險提示(P1-4)—— 需要前後端協定小改。
3. **第三批**:排行榜自己名次(P2-1)、帳號備份提醒(P2-2)、注音範例字(P2-4)、a11y 基礎(P2-6)。
4. **視營運狀況**:AI 對戰墊底(P0-1 長期解)、音效系統、場後統計。
